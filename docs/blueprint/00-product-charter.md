# 产品章程 / 边界 / 用户旅程

## 愿景
不是把“可观测 + AI RCA + ETL + CMDB + 低代码 + 插件商店”全部塞进首版，而是建立一个**可靠的模块化运行底座**。业务模块可安装/升级/卸载、跨机器部署，应用可以安全发现彼此的能力；平台对自身可观察、可诊断、可恢复。第一个有现实价值的业务家族是数据模型与数据接入。

## 目标用户与 Jobs To Be Done
| 人物 | 目标 | 0.0.1 可见交付 |
|---|---|---|
| 平台管理员 | 安装/发布插件、控制权限、确认运行安全 | 包校验、差异预览、安装向导、生命周期与审计 |
| 运维工程师 | 看到节点和插件是否正常、为什么失败、实时日志 | Node/Instance 列表、事件、基础资源指标、日志 Tail、恢复 |
| 插件开发者 | 一套 SDK 独立开发/发布前后端功能 | Template、Manifest/Capability API、CLI、契约测试、Dev Loop |
| 平台用户 | 不刷新/重建平台即可使用新业务功能 | 路由、导航、页面动态注册、错误隔离 |
| 数据工程师 | 接入源并治理结构与执行质量 | 从 0.0.2 开始 Data Catalog / Data Integration |

## 一条可见的 0.0.1 黄金旅程
管理员登录 → 在 Nodes 看到 A/B 两节点已验证身份 → 上传签名 `hello-ops` 全栈包 → 预览权限/依赖/制品 → 安装并指定副本 2 → Node A/B 各运行一个后端 → Web 侧增加 Hello 页面并访问 Gateway API → 查看实例 CPU/内存/健康/运行日志 → 发布 v2（新版本失败时旧版可用）→ 禁用/重新启用 → 卸载保留数据 → 审计可查询。

## 设计不等于实现
UX、接口、表名及配置全部是目标规范。无测试记录的场景不能宣称完成；0.0.1 非企业生产 HA 产品。部署基线仅 Linux Nodes + 可信私网/路由可达；Windows/macOS 仅作为开发客户端（除非另立 ADR）。

## 成功/止损指标（均为验收目标而非实测）
- 0.0.1：不重新构建 Kernel/Web Shell、且不重启 Kernel，成功安装/升级/停用插件；独立后端两个节点就绪；Node 断线状态不造假；断线后恢复对账一致。
- 安全：未经信任的包、越权 capability、节点伪造、越权日志订阅必须拒绝。
- UI：关键链路可凭键盘完成、空/错/等待/未知状态可理解，三宽度两主题截图经人工审阅。
- 0.0.2：从 HTTP/JSON 导入真实数据，经发现/映射/校验进入 Dataset，来源/失败/批次可追溯。
- 止损：若 0.0.1 无法安全热升级并保留服务连续性，则停止加业务插件，先修 Kernel；不增加抽象掩盖失败。
