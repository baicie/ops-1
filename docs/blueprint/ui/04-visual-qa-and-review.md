# UI 视觉审查与可用性验收

## 必须执行的实际审查顺序
1. 阅读目标 Job To Be Done 与业务状态矩阵，先画页面结构（无需代码）。
2. 在组件库中找已有组件，记录新增组件理由；不出现 5 种不同样式的相同状态标识。
3. 实现真实数据/Fixture 状态 LOADING、EMPTY、READY、FAILED、UNKNOWN、FORBIDDEN、PARTIAL。
4. 运行 typecheck、unit、route integration、Playwright（或等效浏览器自动化）并生成以下六张**真实浏览器截图**：1440/1024/390 × Light/Dark。
5. 人工审查截图：信息分组/密度、间距、对齐、状态识别、CTA 层级、文本截断、弹层、表格/日志可读性；记录 P0/P1/P2。
6. 修复后重新截屏对照；不能以截图工具未启动为理由宣称视觉通过。

## 100 分内部质量量表（非公开行业标准）
| 类别 | 分值 | 检查 |
|---|---:|---|
| 信息架构与任务完成 | 25 | 首页和操作入口明确、不迷路 |
| 视觉层次与间距 | 20 | 不堆卡片/无意义色块、字号/对齐统一 |
| 交互完整性 | 20 | loading/error/unknown/权限/撤销/关闭完整 |
| 状态语义正确性 | 15 | 不把部分/失联/无数据显示健康 |
| 响应式与可访问性 | 15 | 三宽度/键盘/对比度/运动偏好 |
| 性能与稳定性 | 5 | 无明显渲染抖动、日志列表有界 |

建议门槛 85/100 且无 P0/P1；关键安全/数据真实性问题无论分数多少均阻止验收。评分须说明执行环境、截图链接和审阅者，不允许模型自评代替真实检查。

## 常见禁止反模式
- Dashboard 上每个字段都变成一个卡片；彩色状态在整个页面泛滥；多余的渐变、巨大空白、过粗边框。
- 页面主要内容不在第一屏；关键动作要通过三个汉堡菜单才找到；无反馈的图标按钮。
- 单屏超宽表格让整个页面水平滚动；390px 下主要操作消失；深色主题文字对比不达标。
- 弹窗套弹窗；一边自动刷新列表一边清除用户筛选；日志不断滚动导致复制文本困难。
- 将 `0`、`null`、`UNKNOWN`、`unavailable` 混为相同展示；AI/插件内部未授权功能仅隐藏菜单。

## 可审查产物
`ui-plan.md`（任务/页面结构/交互）+ `ui-state-matrix.md` + actual screenshots（不进敏感代码库时提供安全链接）+ `visual-review.md` + automation logs。设计 Token 变更单独 PR。
