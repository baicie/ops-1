## 状态机

`PENDING → RUNNING → SUCCEEDED / RETRY_WAIT / FAILED_FINAL`

- Event 与 Job 在同一事务创建（`event_id UNIQUE`，一个 Event 至多一个 Job）。
- Event 响应由 `COLLECTED` 改为 `PENDING` + `jobId`；不再把 202 当采集完成。
- Worker 用 `FOR UPDATE SKIP LOCKED` + 60s lease claim；租约过期的 `RUNNING` 可被其他/重启后的 Worker 接管。
- 成功写 Evidence 后 `SUCCEEDED`；可重试错误（Node/Plugin 不可用、无效响应、上游失败）最多 3 次，退避 15s×attempt；配置/binding/Incident 生命周期/预算/Principal 过期直接 `FAILED_FINAL`。
- 每次 attempt 写 `telemetry.automation.attempt_failed`/`succeeded` 审计（AUTOMATION actor）。

## 恢复语义

- Event 提交后崩溃：Job 已提交，Worker 重启后 claim。
- 采集成功、Evidence 前崩溃：租约过期重试。
- Evidence 已提交、Job 未确认：重试重新采集；Evidence 写入仍受 `(incident,kind,source,contentRef)` 唯一键保护。若重试产生不同字节，可能追加一条新 Evidence（残余，需要在 B1.3b 用 job-scoped content ref 收口）。
- Node 超时/插件重启/PostgreSQL 短暂不可用：归类为可重试（上游错误）。
- Incident 已 CONCLUDED/CLOSED：`append_automation_evidence` 拒绝，Job `FAILED_FINAL`。
