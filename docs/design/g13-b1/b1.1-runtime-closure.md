## 2. 自动采集策略

```
OPSWEAVE_AUTOMATION_SOURCES
{"<plugin>":{"<workspace>":{"<sourceId>":{
  "secretRef":"secretref:...","state":"READY",
  "itemIds":["10401"],"windowSeconds":300
}}}}
```

- `itemIds` 最多 32 个、每个 1–64 字节、无空白；不合法 → 整个 source 配置被跳过（fail closed）。
- `windowSeconds` 30–3600，默认 300。
- 注册表（迁移 0029）保存 `automation_item_ids`、`automation_window_seconds`；`READY` 不要求非空，但自动采集在 items 为空时返回 412 `AUTOMATION_CONFIGURATION_REQUIRED`，不发起 outbound 调用、不写 Evidence。
- 采集窗口：`to = occurredAt`，`from = to - min(source.windowSeconds, principal.windowSeconds)`，最少 30s。
- 请求体同时携带 `budget.maxWindowSeconds/maxItems/maxSamplesPerItem/requestTimeoutMs/maxConcurrency`；插件仍以自己的 ceiling 再 clamp 并在 `clamped` 报告。
- Event 只提供 sourceId/nativeId；不能决定 items、credentialRef、workspace 或 budget。

## 3. 路由约束

`route_for(instance_id, expected_plugin_id)` 只返回：

- `activation_revisions.status='ACTIVE'` 且 publisher `TRUSTED`；
- `plugin_deployments.plugin_id = activation.plugin_id = expected_plugin_id`；
- instance `READY`/`START`、node 未撤销、`READY`、心跳未过期、data endpoint 合法；
- 返回 `node_id/node_generation`，调用方再次与 Principal claims 比较，不一致 → `AUTOMATION_INSTANCE_STALE`。
