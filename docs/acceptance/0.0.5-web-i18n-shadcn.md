## 2. 国际化

- 仓库内自建，无第三方 i18n 依赖：`src/i18n/index.tsx`（Provider / `useT` / `useI18n` / `translate`）
- 目录：`catalogs/en.json` 与 `catalogs/zh-CN.json`，**各 110 键**；`MessageKey` 由 `en` 派生，`zh-CN` 用 `Record<MessageKey, string>` 约束 → **缺键直接编译失败**
- 默认 locale = `en`（冻结）：既有英文文案与 `aria-label="Deployment version"` 逐字不变，Playwright 断言不受影响
- 切换：`[data-testid="language-switcher"]`，持久化到 `localStorage`，刷新保持，`<html lang>` 同步
- 时间格式：`Intl.DateTimeFormat`（UTC、h23），输出与旧实现逐字一致，避免角标断言漂移
- 后端错误：协议枚举值不翻译（可保留在 `data-status`），只翻译展示文案
- 校验：`scripts/check-i18n.mjs` — 缺键双向比对（en↔其他）、孤儿键、未使用键、动态拼键直接报错；接入 CI web job（build 之前）
- 已迁移：`Layout`（导航/顶栏/主题/语言）、`VersionBadge`、`Login`、`Ui.tsx` 全部共享组件（TimeAgo、StatusBadge、CopyButton、ErrorState、Skeleton、Modal、ConfirmDialog、Toast、Progress）

## 4. 本轮发现并修复的运维缺陷（并发部署竞态）

现象：CI 的 deploy 步骤与手工部署同时进行，两者都执行 `docker compose up`，导致 kernel 容器停在 **Created** 状态、3000 端口无监听，预览短时不可用。

修复：`deploy-staging.sh` 增加**主机侧互斥锁**（`flock` on `/var/lib/opsweave-staging/deploy.lock`，默认等待 600s，可用 `OPSWEAVE_LOCK_TIMEOUT` 覆盖）；`--status` 不加锁以保证监控可用。

实测：人为持锁 25s 时，`OPSWEAVE_LOCK_TIMEOUT=5` 的部署被明确拒绝（`another deployment still holds ...`）；锁空闲时部署成功并自证版本一致；持锁期间 `--status` 仍返回 JSON。
