## 三个只有真机才会暴露的缺陷（均已修复）

1. **Kernel/Node 不能是桥接容器**：`nodes.rs:180-232` 只接受 loopback 明文 `data_endpoint`，故二者使用 host 网络；PostgreSQL/Registry 双绑 `127.0.0.1` + `172.17.0.1`，否则插件的 bridge 容器回连不到 DB。
2. **首次部署的 initdb 竞态**：`pg_dump` 在 `POSTGRES_DB` 建好之前执行会 abort；现在有界等待库可查询，只有"无库且从未发布"才按首次初始化继续。
3. **Node 容器的 bind 路径命名空间泄漏**：Node 把实例 token 挂载源（容器内路径）交给宿主 docker daemon，导致 `bind source path does not exist`。修复为**路径一致挂载**（容器内与宿主同路径 `/var/lib/opsweave-staging/node`）。

## 链路约束（未解决，需要决策）

- **云防火墙只放行 3000**：18080/8080/8888/9090 实测全部被丢弃，因此预览端口是主机配置 `OPSWEAVE_PREVIEW_PORT`。
- **GitHub runner → 该主机的持续大流量被掐断**：`docker save | ssh | docker load` 传输 246MB 镜像时接收端 27 分钟 0 字节（小控制流量正常）。当前镜像投递走可用链路（本机→主机 246MB / 10–17s），CI 用 `skip_image_transfer` 跳过投递后完成部署/健康/smoke/摘要。彻底自动化需**国内可拉的镜像仓库**（腾讯 TCR / Docker Hub + 国内镜像源）或**境内 self-hosted runner**。
