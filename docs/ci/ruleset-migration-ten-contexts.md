## Recording the write, and proving it (TASK-13)

`PUT /rulesets/{id}` returns 200 and the resulting ruleset, but a 200 is not
evidence that the ruleset is what was sent. Three comparisons are needed, and each
answers a different question:

| mode | question | when |
|---|---|---|
| (default) | is this payload internally sound? | before anything |
| `--against-live <before.json>` | does it still match the repository? | before the write |
| `--verify-readback <payload> <after.json>` | did the write produce EXACTLY it? | after the write |

```bash
# BEFORE: snapshot, validate, compare to the snapshot
gh api repos/baicie/ops-1/rulesets/26958761 > /tmp/before.json
node tests/ci/check-ruleset-payload.mjs
node tests/ci/check-ruleset-payload.mjs --against-live /tmp/before.json

# WRITE (authorisation required - not part of any automated run)
gh api -X PUT repos/baicie/ops-1/rulesets/26958761 \
  --input docs/ci/ruleset-candidate-ten.json > /tmp/put-response.json

# AFTER: read back and prove nothing else moved
gh api repos/baicie/ops-1/rulesets/26958761 > /tmp/after.json
node tests/ci/check-ruleset-payload.mjs --verify-readback \
  docs/ci/ruleset-candidate-ten.json /tmp/after.json
```

`--verify-readback` fails on three things, and each is a measured input:

- a rule in the payload that is **not** in the read-back
  (`rule "pull_request" is in the payload but NOT in the read-back`, plus
  `PROTECTION LOST: "pull_request" is not on the ruleset after the write`)
- a rule in the read-back that is **not** in the payload
  (`rule "workflows" is in the read-back but NOT in the payload - the write ADDED something`)
- a field that came back different, printed with both sides

### What rollback does NOT restore

It does not undo a merge that happened while the checks were required, and it does
not restore a check that was red when it was rolled back. Rollback changes what
BLOCKS, not what happened.
