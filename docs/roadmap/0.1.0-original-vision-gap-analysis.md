# 0.1.0 Original Vision — Gap Analysis

This document maps the current 0.0.5 code to the long-term AI-assisted incident investigation direction; it does not authorize 0.1.0 implementation.

## Current reuse points

- **PostgreSQL business state**: Catalog datasets, schema revisions, lineage, quality runs/results, Kernel nodes and resource samples.
- **Authorization**: Kernel identity, plugin capability scopes, Gateway-mediated plugin calls.
- **Bounded execution**: Quality run caps, node history limits, retention batches.
- **Product surface**: Pipeline Studio, Jobs, Nodes, Data Catalog, Data Integration, Governance.

## Missing original-vision capabilities

1. **Zabbix / Nebula APM / Metrics / Traces / Logs connectors** — only the generic HTTP JSON integration exists.
2. **Entity / Service / Instance / Host unified identity and temporal topology** — `catalog_entity_types` and node identity exist, but there is no service graph or temporal topology authority.
3. **Incident as investigation entry point** — no incident aggregate, timeline, severity, ownership, or correlation model.
4. **Query Gateway for telemetry** — current Gateway authorizes plugin APIs; it is not a bounded telemetry query service with source-aware budgets.
5. **Evidence / Hypothesis / Verification / RCA Engine** — no evidence graph, hypothesis lifecycle, verification protocol, or RCA evaluator.
6. **Rust Investigation Agent** — no bounded multi-round read-only investigation agent.
7. **Human Verdict / Golden Dataset** — no incident labels, reviewer verdict workflow, or replayable golden fault corpus.
8. **Investigation Workspace** — current UI is operational control-plane pages, not an incident-centric investigation workspace.

## Overbuilt / scope risk

The current generic Pipeline Studio, plugin lifecycle, and broad governance UI are useful platform foundations but are not a substitute for incident investigation. Do not make Studio parity a prerequisite for the first 0.1.0 RCA path.

## Minimal 0.1.0 golden path

```text
Incident created from one real alert
  → link Entity/Host/Service
  → authorized bounded query of one telemetry source
  → persist Evidence with provenance
  → produce one Hypothesis and one Verification step
  → Human Verdict
  → replay in Golden Dataset
```

Recommended order: incident/evidence schema → one connector (Zabbix or Nebula) → bounded Query Gateway → evidence timeline UI → hypothesis/verification → human verdict → golden replay. Do not add a second plugin framework or a new database.
