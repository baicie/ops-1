# 0.1.0 Investigation Foundation — Design

Status: design only. 0.0.5 release gates are not fully closed, so no 0.1.0 runtime code is introduced.

## Reuse map

| Capability | Reuse | Gap |
|---|---|---|
| Identity / RBAC | Kernel users, sessions, capability grants | Incident/evidence object scopes |
| Telemetry query | Data Integration HTTP JSON + Gateway | bounded Query Gateway for Zabbix/APM/logs |
| Persistence | PostgreSQL 17 | incident/evidence/hypothesis tables |
| Execution | Node + Catalog quality/lineage | read-only Rust investigation runner |
| UI | React platform and extension host | Incident Investigation Workspace |

## Domain model

```text
Incident(incident_id, title, severity, status, opened_at, closed_at)
InvestigationRun(run_id, incident_id, status, principal, started_at, completed_at)
Evidence(evidence_id, incident_id, run_id, source_ref, entity_ids,
         time_range, observed_at, status, data_mode, query_fingerprint,
         payload_digest, payload_ref, warnings)
Hypothesis(hypothesis_id, run_id, statement, status, confidence, rationale)
Verification(verification_id, hypothesis_id, tool_call_id, result, evidence_ids)
Report(report_id, run_id, summary, evidence_refs, uncertainty, verdict)
HumanVerdict(report_id, verdict, reviewer, comment, decided_at)
```

Evidence status is one of `AVAILABLE | NO_DATA | PARTIAL | STALE | UNAVAILABLE | FORBIDDEN`. The server—not the model or agent—sets source_ref, query_fingerprint, payload_digest, captured_at, status and authorization scope.

## Bounded tool contract

```text
metric.query(entity_ids, source_ref, from, to, max_points, deadline)
trace.search(service_ids, from, to, max_spans, deadline)
log.search(service_ids, from, to, max_records, max_bytes, deadline)
entity.relations(entity_ids, depth<=2, max_nodes)
incident.context(incident_id)
```

Every call validates principal, tenant/workspace, entity scope, source scope, time range, record/byte caps and deadline. No arbitrary SQL, shell or HTTP.

## Minimal golden path

```text
Incident -> authorize -> Evidence Pack -> deterministic hypothesis
 -> verification (one bounded query) -> Report snapshot -> Human Verdict
```

If a real Zabbix/APM/log source is absent, only fixture-mode tests may run and must be labelled `FIXTURE_ONLY`; they cannot be reported as multi-source production validation.

## Storage and transactions

- Incident state is authoritative in the existing platform control plane; do not create a second incident authority.
- Evidence payloads are immutable blobs referenced by digest; metadata lives in PostgreSQL.
- Investigation run ledger is append-only; attempt cancellation is terminal and cannot produce a report.
- Human verdict is a separate row and never overwritten by an agent.

## UI slice

Read-only Investigation page: Incident context, evidence list with status badges, hypothesis list with support/counter-evidence, investigation status and report snapshot. Keep current navigation; do not build a general agent chat/workflow product.

## Test and release gates

```text
fixture incident -> evidence -> hypothesis -> report
authorization: viewer read-only, operator execute, admin verdict
no_data/stale/unavailable never rendered as normal
cancelled run cannot emit report
payload digest and evidence reference checks
one real connector adapter contract test before claiming multi-source support
```

## Explicit non-goals

```text
No new microservice, event bus, workflow engine or plugin framework.
No automatic RCA product claim in 0.0.5.
No model-generated fact without evidence references.
```
