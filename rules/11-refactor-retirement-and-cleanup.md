# R-11 重构、退役与清理规则

适用于移动/重命名/删除模块、应用、包、目录，以及任何"代码搬走了、引用留下了"的改动。本规则的目标不是整洁，而是**让门禁保持真实**：一次搬迁之后，检查必须仍然检查，失败必须仍然可见。

背景与已发生的实例见 [ADR-022](../docs/adr/ADR-022-platform-core-and-applications.md) §2.2、[G14.2 实现状态](../docs/IMPLEMENTATION_STATUS.md)；机器检查为 [`tests/ci/check-retired-paths.mjs`](../tests/ci/check-retired-paths.mjs)。

## 退役必须原子完成（MUST）

- MUST：退役一个路径（删除 `apps/x`、重命名包、拆分应用）时，同一个变更内更新全部活引用：代码、`package.json` / `pnpm-workspace.yaml`、`.github/workflows/**`、`tests/ci/**`、`tests/runtime/**`、`tests/acceptance/**`、扫描类门禁脚本、以及**描述当前树的文档**（`README.md` 仓库地图、`AGENTS.md`、`rules/**`）。
- MUST：删除而不是保留第三个入口。拆分成两个应用时，旧入口不能作为"兼容别名"留下——一个同时渲染两个 Surface 的入口会还原掉拆分本身要消除的属性（ADR-022 §2.2、G14.2）。
- MUST：区分**活文档**与**历史记录**。`docs/design/**`、`artifacts/**`、`docs/IMPLEMENTATION_STATUS.md` 中带日期的章节是当时事实的证据，**不得**回写旧路径；它们描述的是"当时如此"，改写等于伪造历史。只有声称"现在是什么"的文本才必须跟代码同步。
- SHOULD：检索退役标识符时用 `git grep <old-path>`，并把命中分为"活引用（必须改）"与"历史记录（必须不改）"两类再动手。

## 门禁不得静默空转（MUST）

一次搬迁最常见的失败不是报错，而是**检查照样变绿**。以下空转已在本仓库实测发生，新增/修改门禁时必须逐条排除：

- MUST NOT：依赖"匹配不到就成功"的过滤器。`pnpm --filter <不存在的包> build` 在 pnpm 10 下**退出码为 0**（实测），CI 会绿着构建了零个包。必须加 `--fail-if-no-match`（实测：无匹配退出 1，有匹配退出 0）。
- MUST NOT：在 `set -euo pipefail` 下把扫描结果赋给变量后再断言。`X="$(grep -rn ... "$MISSING_DIR" | wc -l)"` 会在**赋值处**因 grep 失败而中止整个脚本（实测 exit=2），断言根本没执行，既不算通过也不报告——检查从"失败"退化成"没有发生"。
- MUST：扫描类门禁声明多个源码根时，**根不存在必须失败**，不得用 `.filter(existsSync)` 静默剔除。剔除等于"新包忘了加进来"这件事永远不可见；本仓库 `scripts/check-i18n.mjs` 的注释已写明该清单是显式的，因此它必须 fail-closed。
- MUST：门禁必须报告**扫描量**（文件数 / 根数 / 键数），并在扫描量为 0 时失败。只打印 "OK" 的门禁无法区分"都通过"和"什么都没读"。
- MUST：新增门禁或搬迁门禁时验证其**非空转**：故意改坏一个被检查的文件（或临时改名一个根目录），确认门禁**真的变红**，再把证据写进提交说明。只证明"现在是绿的"不算验证。

## 边界必须可检查（MUST）

- MUST：`packages/*` 不得 import `apps/*`；`apps/a` 不得 import `apps/b`。这条要么由构建配置强制，要么由脚本强制，不能只写在文档里。
- MUST：共享层只放两端都合法需要的东西。搬类型时要判断方向：属于平台的概念进 `packages/platform-client`，属于业务域的类型留在业务应用内（G14.2 的 `types.ops.ts` 即此例）。
- MUST：Kernel 侧的静态资源挂载必须按前缀解析到**对应应用的 `index.html`**；用一个 shell 回答所有前缀会让浏览器挂载错误的路由器，表现为"页面加载成功但所有子路由 404"。

## 清理的完成判据（MUST）

一次清理只有在以下三点同时成立时才算完成，且必须在提交说明中给出真实输出：

1. `git grep <retired>` 在活文档与可执行文件中零命中；历史记录中的命中已逐条确认应保留。
2. 每个受影响的门禁在被**故意破坏**时变红（记录命令与退出码）。
3. 受影响的构建/测试**真实运行过**；"路径已更新"不等于"测试通过"，未运行的项记 `NOT_RUN`。

- Gate：拆分或搬迁类 PR 必须附上上述三项证据；缺任一项不得以"重构已是机械操作"为由跳过。
